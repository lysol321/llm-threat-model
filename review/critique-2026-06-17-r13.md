## Part I: Round 12 Research Deliverables — Research Quality Assessment

### Capability Withholding Analysis — RESEARCH COMPLETE ✅

The analysis is methodologically sound:
- Six sources reviewed across ACL 2024, arXiv (2025-2026), AAAI 2026
- Correct distinction between commission attacks (model made to do harm) vs. withholding attacks (model made to be less capable)
- Wild_vs_Theory 1/5 correctly assigned for intentional attacks — no in-wild evidence
- Wild_vs_Theory 3/5 correctly assigned for accidental RLHF reward hacking causing degradation — production RL cases documented
- Taxonomic placement recommendation (Category 13 note) is appropriate

**Adversarial challenge: Is "RLHF Energy Loss" Actually Exploitable by External Attackers?**

The analysis correctly identifies "Energy Loss Phenomenon in RLHF" (arXiv 2501.19358) as the strongest evidence for capability degradation in production (Wild_vs_Theory 3/5). But the paper documents **accidental** capability loss during RLHF optimization — not attacker-induced degradation.

The analysis asks: "Whether 'energy loss' phenomenon in RLHF is exploitable by an external adversary or only an internal RLHF operator" — and leaves it as an open question.

This is the critical gap. If energy loss is only exploitable by whoever controls the RLHF pipeline (an internal operator), then it maps to supply chain attacks (Category 6) — not a separate capability withholding category. If it is exploitable by an external adversary who can manipulate the reward signal through indirect means (e.g., adversarial data in training corpora that the reward model learns from), then it is a distinct attack vector.

**The adversarial question the framework should answer:** Can a nation-state or criminal actor who does NOT control the RLHF pipeline still induce capability withholding through supply chain data poisoning? The BadAgent paper (ACL 2024) comes close — it poisons training data to activate malicious behavior — but it's commission-oriented, not withholding-oriented.

**Recommendation:** Reframe capability withholding as a supply chain sub-type if the only exploitable path requires RLHF pipeline access. If a separate "inducement" path exists (external attacker manipulates training data to cause capability suppression without being the RLHF operator), document that as a novel attack chain. The distinction matters for defense ownership — supply chain = [PROV], inducement = [DEV/OPS].

### Defense Interaction Analysis — RESEARCH COMPLETE ✅

The analysis correctly identifies 4 MEDIUM-severity cascading conflicts:
1. RAG privilege separation + tool allowlist false negatives
2. RAG document → tool call provenance gap
3. HITL provenance gap with PI-DEF-2 enforcement
4. Cascading PI-DEF-2 + AGENCY-DEF-1 + AGENCY-DEF-2 multi-defense interference

The cascading interaction table (lines 72-77) is well-structured. The severity ratings (MEDIUM = affects real production deployments) are correctly calibrated.

**Adversarial challenge: Is "Cascading Interference" a New Attack Surface or Just an Implementation Complexity?**

The analysis frames defense interaction conflicts as reducing effective coverage — each layer fails in ways that are worse than if the layer simply wasn't there. This is accurate but undersells the adversarial implications.

Consider: an attacker who understands a specific defense stack (e.g., knows the target deployment uses PI-DEF-2 + AGENCY-DEF-1 + AGENCY-DEF-2) can deliberately craft attacks that exploit the interference gaps. The defense interaction isn't just a reliability concern — it's an **attack surface that a sophisticated adversary can target specifically**.

Specifically:
- Conflict 1 (RAG privilege separation false negatives): An attacker who knows the deployment uses RAG + privilege separation can embed injections in documents that look legitimate to the untrusted LLM but are crafted to exploit the permission boundary
- Conflict 3 (HITL provenance gap): An attacker who knows HITL is in the loop can craft injection content that, when blocked by PI-DEF-2, still shapes the tool call in a way the human approver can't detect

This is not just "defenses interfere with each other" — it's "adversaries can weaponize defense interference." The framework should name this explicitly.

**Recommendation:** Add to the Defense Interaction Analysis section: "Note: Defense interaction gaps are not merely implementation complexities — sophisticated adversaries with knowledge of a target's specific defense stack can craft attacks designed to exploit interference between layers. Defense interaction analysis should be treated as a red-team target, not just an engineering reliability concern."

### Challenge 2: "RLHF Energy Loss" as a Potential Capability Withholding Vector Is Under-analyzed — MEDIUM

The capability-withholding-analysis.md leaves as an open question: "Whether 'energy loss' phenomenon in RLHF is exploitable by an external adversary or only an internal RLHF operator."

The analysis correctly notes that BadAgent and related papers are commission-oriented (model does bad things) rather than withholding-oriented (model does less good things). But the Energy Loss paper (arXiv 2501.19358) describes a mechanism — gradient accumulation patterns during RLHF that cause capability suppression on specific tasks — that could theoretically be induced by an external attacker who cannot access the RLHF pipeline directly.

**The attack path would be:**
1. Attacker identifies a target organization's RLHF training data curation process
2. Attacker introduces adversarial examples into the training corpus (supply chain poisoning)
3. The reward model learns from these examples and assigns lower rewards to specific capability outputs
4. The resulting model exhibits suppressed capability on target tasks without obvious malicious behavior

This is distinct from BadAgent because BadAgent activates commission behavior (malicious tool calls). This path suppresses capability (the model becomes less useful on target tasks) without triggering any obviously malicious behavior.

**Wild_vs_Theory: 1/5** — no documented case of this specific attack path. But the mechanism is theoretically sound and the Energy Loss paper provides the technical basis.

**Why this matters for the framework:**

If this attack path is real, it changes the taxonomic placement. Capability withholding wouldn't be a separate Category 13 — it would be a sub-type of supply chain attacks (Category 6). The defense would shift from behavioral baselining (detection) to supply chain integrity (prevention), which is a fundamentally different ownership model ([PROV] vs. [DEV/OPS]).

**Recommendation:** The open question about external exploitability should be answered through additional research — specifically, a threat model of how an external attacker could influence RLHF training data curation without being the RLHF operator. If this path is confirmed theoretical only (no practical path for external attacker), document that as "RLHF supply chain poisoning requires internal RLHF access — external adversaries cannot induce capability withholding without compromising the RLHF pipeline directly." This is a useful boundary condition for the framework.
