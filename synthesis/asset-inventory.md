# LLM Threat Modeling — Asset Inventory

**Version:** 1.1 (agentic memory, skill, identity, relay, and provenance assets)
**Date:** 2026-07-20
**Status:** Living document — re-evaluate when system architecture changes

---

## Purpose

Every threat model must answer: "What exactly are we protecting?" Without a formal asset inventory, risk scores are uncalibrated — a deployment with no sensitive data, no API keys, and no tool integrations has fundamentally different risk than one with all three. This document enumerates every asset the framework implicitly or explicitly protects, organized by asset class.

**How to use this document:** Use the Asset Verification Checklist at the end to confirm which assets exist in your deployment. The threats and risk scores in this framework apply only to assets that are actually present.

---

## Asset Classes

Assets are organized into five classes:

1. **Data Assets** — Information processed, stored, or generated by the LLM system
2. **Model Assets** — The AI model itself, its weights, and its training/inference components
3. **Infrastructure Assets** — The compute, network, and execution environment
4. **Trust Boundary Assets** — The security boundaries and authentication mechanisms that protect other assets
5. **Intellectual Property Assets** — Proprietary business logic, prompts, and organizational knowledge

## 1. Data Assets

### 1.1 User Data

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **User prompts / queries** | Text input from end users | Contains context about user intent, may include sensitive information | Chain A, Cat 5 |
| **Conversation history** | Full multi-turn conversation context | Contains accumulated sensitive context across turns; exfiltration exposes entire session | Chain A, Cat 7 |
| **Personal data (PII)** | Names, emails, financial data, health data in user inputs or RAG documents | GDPR Article 17 exposure; identity theft; regulatory breach notification | Cat 7, Cat 4 |
| **User-uploaded documents** | Files uploaded to the LLM (PDFs, images, structured data) | May contain proprietary information; poisoning attacks can target uploaded content | Cat 1, Cat 10, Cat 4 |
| **User-generated content** | Content created by users and submitted to the LLM for processing | Can be manipulated via prompt injection; poisoning vector | Cat 1, Cat 10 |

### 1.2 Organizational Data

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **RAG document corpus** | Organizational knowledge base, internal documents, policies, code | Exfiltration exposes proprietary knowledge; poisoning corrupts model behavior | Chain A (1b), Cat 4 |
| **Training / fine-tuning data** | Proprietary datasets used to fine-tune models | IP theft; poisoning/corruption; GDPR exposure | Cat 4, Cat 6 |
| **Embedding vectors** | Numerical representations stored in vector database | Can leak training data; inversion attacks reconstruct inputs | Cat 7 |
| **System prompts** | Security controls, API keys, proprietary instructions | Extraction bypasses all alignment-based security controls | Cat 5, Chain A |
| **Developer messages** | Task definitions, business logic encoded in prompts | Same as system prompts — proprietary instructions | Cat 5 |
| **API keys / secrets** | Credentials embedded in prompts, tool configurations, or environment | Direct system compromise; financial loss; lateral movement | Chain B, Cat 5 |
| **Session state** | Active conversation session data | Account takeover; context manipulation | Cat 12 |
| **Agent state (shared)** | Shared messages, context store, graph state in multi-agent systems | Poisoning propagation across agent chain | Chain C |

### 1.3 Operational Data

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Tool call logs** | Records of tool executions with parameters and outputs | Forensics pivot; privilege escalation evidence; audit compliance | Cat 5 |
| **RAG retrieval logs** | Records of what documents were retrieved for each query | Context of what the model knows about the user/organization | Cat 5 |
| **Inter-agent messages** | Communications between agents in multi-agent systems | Poisoning vector; privilege escalation evidence | Chain C |
| **HITL approval records** | Human-in-the-loop approvals with context provenance | Forensic evidence; accountability | Cat 12 |
| **API usage / quota data** | Billing records, usage patterns | Financial DoS; billing fraud | Cat 8 |

### 1.4 Derived Data

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Model outputs / completions** | Generated text, code, summaries, decisions | Misinformation; downstream harm; deceptive practice liability | Cat 11 |
| **Tool return values** | Outputs from tools called by the LLM | Injection vector into agent context; data exfiltration via tool output | Chain C, Cat 11 |
| **Retrieved context (RAG results)** | Documents and data retrieved in response to queries | Poisoning; information disclosure | Chain A (1b), Cat 4 |
| **Derived embeddings** | Embeddings computed from user/organizational content | Training data extraction; membership inference | Cat 7 |

### 1.5 Task / Validator / Data (TVD) Harness Assets

These are the assets Internal Safety Collapse (Category 14) actually attacks. They
exist only in deployments that **execute** a task/validator/data harness — eval,
fine-tuning, data-generation, code-repair, or autonomous-tool workflows. Plain
inference consumers with no harness do not hold these assets (Cat 14 = N/A). See
`threat-taxonomy.md` Category 14 applicability boundary.

| Asset | Description | Why It's a Target | Threat Category | Owner |
|-------|-------------|-------------------|----------------|-------|
| **Task definitions** | The professional activity the model is asked to complete (eval, test, repair, dataset fill) | Attacker-shaped task framing drives autonomous harmful completion | Cat 14 | [DEV] / [PROV] |
| **Validator harness code** | Code/schema/test/eval harness that checks output completion but enforces no semantic safety bounds | Format-only validators force the model to "complete" into harmful content | Cat 14 | [DEV] |
| **Schemas / tests / eval scripts** | Machine-checkable acceptance criteria the model must satisfy | Acceptance gate with no safety semantics is the ISC trigger | Cat 14 | [DEV] |
| **Incomplete / placeholder data** | Intentionally partial data the model must fill to satisfy the validator | Gap-filling is where harmful generation emerges | Cat 14 | [DEV] / [OPS] |
| **Generated harmful intermediate artifacts** | Content the model produces to pass the validator before downstream use | Stored/actioned/evaluated without semantic safety review | Cat 14, Cat 11 | [OPS] |
| **Model-completion-generated fine-tuning / eval datasets** | Datasets produced by feeding model output back into training/eval | Poisoned or harmful completions propagate into downstream models | Cat 14, Cat 4 | [OPS] / [PROV] |
| **Model-host / agent-platform safety-eval harness** | Provider-side or platform safety/eval pipeline that submits TVD-shaped tasks | Provider-side ISC scanning gap (ISC-DEF-3) | Cat 14 | [PROV] |

## 2. Model Assets

### 2.1 Model Weights and Architecture

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Base model weights** | The core LLM parameters (self-hosted deployments) | IP theft; model extraction; silent exfiltration via custom inference | Chain B, Cat 6 |
| **LoRA / PEFT adapters** | Low-rank adaptation weights applied to base model | Remove safety alignment; behavioral modification; adapter swap attack | Chain B (1b), Cat 3 |
| **Fine-tuning data** | Proprietary datasets used for supervised fine-tuning | IP theft; training data extraction; **distillation exposure** of proprietary data through fine-tuned artifact | Cat 4, Cat 6 |
| **Fine-tuned model artifact** | The resulting model from fine-tuning on proprietary data | Inherits base model properties + introduces new behavioral risks; **proprietary training data exposed to extraction via the fine-tuned artifact** | Cat 4, Cat 6 |
| **Reward model (RLHF)** | The reward model used for RLHF training | Corruption of alignment; capability degradation; Cat 13 Addendum | Cat 13 Addendum |
| **RLHF preference data** | Human preference annotations used for alignment | IP theft; manipulation of model behavior | Cat 13 Addendum |
| **Safety alignment / policy** | The aligned behavior of the model enforced via RLHF or DPO | Can be removed via fine-tuning or adapter swap | Cat 3 |
| **Tokenizer configuration** | Vocabulary, special tokens, encoding rules | Manipulation of input processing; bypass of input filters | Cat 3 |
| **Inference framework** | Transformers, vLLM, llama.cpp, etc. | Exploitation of framework vulnerabilities; upstream supply chain | Cat 3 |
| **Model serving configuration** | Quantization settings, batching config, memory allocation | Affects model behavior under resource constraints | Cat 8 |

### 2.2 Model Execution Components

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Custom inference code** | `__init__`, `forward()`, custom forward hooks in model repository | Silent exfiltration on model load (JFrog/ReversingLabs confirmed); backdoor triggers | Chain B (1a.1), Cat 3 |
| **ML dependencies** | PyTorch, TensorFlow, numpy, sentence-transformers, etc. | Supply chain compromise; dependency confusion attacks | Cat 3 |
| **Custom pre/post-processing** | Input normalization, output filtering scripts | Manipulation of model I/O; exfiltration payload injection | Cat 11 |

## 3. Infrastructure Assets

### 3.1 Compute and Runtime

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Inference compute (GPU/CPU)** | GPU instances or CPU containers running model inference | Resource exhaustion DoS; co-tenant data leakage in shared GPU environments | Cat 8 |
| **Container runtime** | Docker, containerd, podman managing inference containers | Container escape; lateral movement; resource hijacking | Cat 3, Cat 8 |
| **Model serving endpoint** | HTTP endpoint or API gateway for model inference | Direct attack surface; API abuse; quota exhaustion | Cat 8, Cat 1 |
| **Memory / VRAM** | Runtime memory containing model state, context, activations | Memory side-channel attacks; context extraction | Cat 5, Cat 7 |

### 3.2 Tool Integrations

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Email / messaging integration** | Email send/read, Slack, Teams tools accessible to LLM | Data exfiltration; social engineering; unauthorized communication | Chain A |
| **Webhook / HTTP client** | Outbound HTTP call capability | Data exfiltration to attacker-controlled endpoints; pivot | Chain A |
| **File system access** | Read/write access to filesystem via LLM tools | Data exfiltration; configuration manipulation; persistence | Chain A |
| **Database access** | SQL or NoSQL query capability via LLM tools | Data exfiltration; data manipulation; unauthorized queries | Chain A |
| **Code execution environment** | Sandbox for running generated code | Code injection; system compromise; resource exhaustion | Cat 2 |
| **Search / web access** | Web search or web scraping capabilities | Information gathering for attacks; SEO manipulation for indirect PI | Chain A (1b.2) |
| **Cloud API credentials** | AWS/GCP/Azure credentials accessible to LLM tools | Lateral movement; resource hijacking; data exfiltration | Chain A |
| **CI/CD integration** | Access to deployment pipelines via LLM tools | Supply chain compromise; malicious model deployment | Cat 3 |

### 3.3 Data Storage

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Vector database** | Chroma, Pinecone, Weaviate, pgvector storing embeddings | Embedding inversion; data exfiltration; poisoning | Cat 7, Cat 4 |
| **Document store** | RAG backend (Elasticsearch, MongoDB, etc.) | Document poisoning; data exfiltration | Cat 4 |
| **Model registry** | HuggingFace, AWS SageMaker, Azure Model Catalog | Adapter swap; malicious model publication | Chain B, Cat 3 |
| **Object storage** | S3, GCS storing model artifacts, documents | Malicious artifact substitution; data exfiltration | Cat 3 |
| **Secret store** | Vault, AWS Secrets Manager, environment variables | API key exfiltration; credential theft | Chain B, Cat 5 |

### 3.4 Network and Egress

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Network egress from inference** | Outbound internet access from inference environment | Silent exfiltration channel (Chain B); C2 traffic | Chain B |
| **MCP server** | Third-party MCP server for tools/data | Compromised server returns poisoned data; C2 | Chain C |
| **A2A channel infrastructure** | Network channel for inter-agent communication | Message interception; impersonation; injection | Chain C |
| **Internal network** | VPC/subnet containing inference and tool environments | Lateral movement from compromised inference environment | Cat 3 |

## 4. Trust Boundary Assets

These assets are the security controls themselves — compromise of these assets defeats all other defenses.

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Instruction hierarchy** | System prompt authority over model behavior | Extraction = all alignment controls bypassed | Cat 5, Cat 1 |
| **Tool permission manifest** | Registry of allowed tools and their permission scopes | Manipulation enables unauthorized tool use | Cat 2 |
| **AIBOM signing keys** | Private keys used to sign model artifacts | Compromise = all AIBOM verifications are false | Cat 3 |
| **Sigstore trust anchor** | OIDC identity provider for model signing | Root of trust for model provenance | Cat 3 |
| **HITL approval authority** | Identity and credentials for human approvers | Compromise enables one-click unauthorized actions | Cat 12 |
| **MCP server identity** | Authentication credentials for MCP server access | Impersonation of legitimate MCP server | Chain C |
| **A2A peer credentials** | TLS certificates, API keys for A2A authentication | Impersonation; message injection | Chain C |
| **Log integrity infrastructure** | Immutable append-only log storage | Log manipulation erases attack evidence | Cat 5 |

## 5. Intellectual Property Assets

| Asset | Description | Why It's a Target | Threat Category |
|-------|-------------|-------------------|----------------|
| **Proprietary system prompts** | Business logic, security controls, proprietary instructions in prompts | Theft of competitive advantage; jailbreaking techniques | Cat 5 |
| **Custom fine-tuned model weights** | Domain-specific adaptations (legal, medical, financial) | IP theft; competitive intelligence | Cat 6, Cat 3 |
| **Domain-specific adapters (LoRA)** | Specialized fine-tuning for vertical markets | IP theft; behavior modification | Cat 3, Cat 6 |
| **RAG corpus (organizational knowledge)** | Internal documents, proprietary databases, expert knowledge | Corporate espionage; competitive intelligence | Cat 4, Chain A |
| **Training data curation methodology** | Methods for selecting and cleaning training data | Theft of ML expertise | Cat 4 |
| **Prompt engineering artifacts** | Library of effective prompts for specific tasks | Theft of ML operational knowledge | Cat 5 |

## Crown Jewel Assets (Top 10 Priority List)

These are the assets whose compromise causes the most severe impact. Every deployment should explicitly assess whether these assets are present and protected:

| # | Asset | Why It's a Crown Jewel | Primary Threat |
|---|-------|----------------------|----------------|
| 1 | **API keys / secrets in prompts or environment** | Direct system compromise, financial loss, lateral movement | Chain B, Cat 5 |
| 2 | **User data / conversation history** | Privacy breach, regulatory notification, reputational harm | Chain A, Cat 7 |
| 3 | **RAG document corpus** | Proprietary knowledge theft, poisoning to corrupt behavior | Chain A (1b), Cat 4 |
| 4 | **Instruction hierarchy / system prompt** | Bypasses all alignment controls | Cat 5, Cat 1 |
| 5 | **Tool execution environment** | Remote code execution equivalent via LLM agency | Chain A, Cat 2 |
| 6 | **Fine-tuning data / reward model** | Model behavior corruption, alignment removal | Cat 4, Cat 3 |
| 7 | **Network egress path from inference** | Silent exfiltration channel; C2 channel | Chain B |
| 8 | **HITL approval mechanism** | One-click unauthorized actions without human review | Cat 12 |
| 9 | **Embedding vectors / vector database** | Training data extraction; GDPR exposure | Cat 7 |
| 10 | **AIBOM / Sigstore signing keys** | Root-of-trust compromise; all model provenance false | Cat 3 |

**On foreign frontier lab weights (verified official):** Models downloaded from the originating lab's official repository with cryptographically verified signatures represent the **lowest supply chain risk** configuration for model assets — see assumption B5. The Crown Jewel list above applies to your organization's own model artifacts, fine-tuned derivatives, and training data. A verified official base model used for inference-only (no custom hooks) with your RAG, tool, and agent surfaces is the baseline low-risk starting point.

## Asset Valuation Tags

Assets should be tagged with both **classification** and **ownership** to drive defense prioritization:

### Data Classification Tags

| Tag | Definition | Examples |
|-----|-------------|----------|
| **PUBLIC** | Information that can be freely disclosed | Marketing content, public documentation |
| **INTERNAL** | Non-sensitive organizational information | Internal policies, non-PII operational data |
| **CONFIDENTIAL** | Sensitive business information | Product roadmaps, financial data, customer lists |
| **RESTRICTED** | Highly sensitive data with regulatory or legal implications | PII, health data, credentials, trade secrets |

### Ownership Tags

| Tag | Definition | Examples |
|-----|-------------|----------|
| **[DEV]** | Developer-controlled asset | System prompts, tool definitions, model weights |
| **[OPS]** | Operator-controlled asset | Infrastructure configuration, network policies, quotas |
| **[PROV]** | Provider-controlled asset | API keys issued by provider, model hub metadata |

### Asset-to-Threat Mapping (Crown Jewels)

The following maps the **Crown Jewel Top 10** assets to the threat categories that target them. It covers the highest-priority assets only; the full 50+ asset inventory should be threat-mapped by extending this pattern.

| Asset | Threat Categories That Target It |
|-------|-------------------------------|
| User prompts / conversation history | Chain A, Cat 5, Cat 7 |
| RAG document corpus | Chain A (1b), Cat 4 |
| API keys / secrets | Chain B, Cat 5 |
| System prompts | Cat 5, Cat 1 |
| Tool execution environment | Chain A, Cat 2 |
| Model weights / adapters | Chain B, Cat 3, Cat 6 |
| Embedding vectors | Cat 7 |
| Network egress path | Chain B |
| Fine-tuning / RLHF data | Cat 4, Cat 13 Addendum |
| Instruction hierarchy | Cat 1, Cat 5 |
